MP4/ISO-BMFF ftyp brand detection samples

One file per major/compatible brand, generated with ffmpeg. Used to verify mmmagic/wi_magic detection (see WI-44553 and the follow-up brand-coverage ticket).

Each brand is on its own isolated page - putting many <video> elements on one page was found to trigger a separate, unrelated WI video-rendering issue (confirmed: the exact same file plays fine in isolation but not when many other videos share the page), so this index intentionally avoids embedding any <video> tags directly.

Already covered by unplayable.mp4 at the repo root (compatible brands: iso4/hvc1/isom) - not duplicated here.

cmfc

Video-only (no audio), H.264 (libx264), major and compatible brand both cmfc. Re-encoded from a clean H.264 source rather than copying unplayable.mp4's HEVC stream, which has the WI-44553 defect.

cmfs

Video-only (no audio), H.264 (libx264), major brand cmfs. Re-encoded from a clean H.264 source for the same reason as cmfc.

av01

Real AV1 encode (libaom-av1) - ffmpeg tags the av01 compatible brand automatically.

av01_major

Same AV1 content as av01, but with av01 as the major brand (no isom). Needs the av01 wi_magic rule to be detected.

hvc1_major

Clean HEVC (libx265, video-only) with hvc1 as the major brand (no isom). Needs the hvc1 wi_magic rule to be detected.

hvc1_remux

Control for hvc1_major: the exact stream and audio of unplayable.mp4, copied with hvc1 as the major brand and moov moved to the front.

hvc1_major_faststart

Control for hvc1_major: the same x265 video with moov moved to the front (faststart), hvc1 major brand.

hev1

Brand forced via ffmpeg's -brand override; underlying stream is the same HEVC content as unplayable.mp4 (has audio, so the WI-44553 defect should only blank the video, not abort the whole load).

avc3

Real H.264 encode (libx264) with in-band parameter sets; brand forced via -brand override.

vp09

Real VP9 encode (libvpx-vp9); brand forced via -brand override (ffmpeg doesn't tag it automatically).

vp8

Not an mp4 - a VP8 WebM (Matroska) file, 1080p 10s, from test-videos.co.uk. ffmpeg's mp4 muxer can't put VP8 in an mp4, so this is the closest real-world VP8 sample; it exercises WebM detection rather than an ftyp brand.
